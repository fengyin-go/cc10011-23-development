# 采集调度策略管理工具

离线版采集调度策略配置工具，涵盖站点登记、模板编排、代理轮换、限速调节、反爬策略、增量水位与结果校验规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-strategy-studio:entries` 这一项，或调用 `resetModule(模块)`。

## 原子落盘子系统

数据落盘页（`/storage`）内置「原子落盘工作台」，结果校验页（`/validator`）内置「数据落盘分区清单核对」，
模拟真实落盘引擎的可见性语义，持久化在独立键 `scraper-strategy-studio:landing`：

- **同事务原子提交**：分区预留、文件写入、可见版本切换在一次持久化事务里完成（`landing-store.ts` 的 `commit`），
  下游只读取数据落盘分区清单（manifest）中的完整文件，临时文件留在 `.tmp` 永远不进清单。
- **状态机**：分区文件经历 预留 → 写入 → 切换 → 归档；写入失败停在「失败」，不会顶替上一版，恢复时清单回到最后完整版本。
- **并发与幂等**：同一分区并发覆写由串行护栏拦截，同一 `requestId` 重复提交复用批次，清单里每个分区至多一个当前项。
- **两种切换策略**：「完成后立即切换分区指向」与「等旧版本读取会话结束后再切换」；读取会话存活期间的换版登记为冲突，
  工作台比较两种处置的文件可见时间并支持仲裁，冲突单带结果校验状态供复核。
- **中断恢复**：故障注入可模拟写入失败与进程中断；恢复从最后一次成功检查点接续，已完成分区不重写，当天结果已留存。
- **校验门**：结果校验同步读取分区清单，未完成/待切换分区不进入校验范围；校验通过后复核固化最终形态。
- 无头仿真测试：`cd frontend && npm run test:landing`（esbuild 打包引擎后在 Node 内跑 10 个场景 54 项断言）。
